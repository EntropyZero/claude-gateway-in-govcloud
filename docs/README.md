# docs/ — what lives where

| Folder | Contents | Audience |
|---|---|---|
| [`ato/`](ato/) | The ATO package: [`architecture.md`](ato/architecture.md) (diagrams + secrets/SG/encryption inventories), [`conops.md`](ato/conops.md) (Concept of Operations), [`network-access-controls.md`](ato/network-access-controls.md) (who-can-talk-to-what deep dive), [`security-assessment-2026-07.md`](ato/security-assessment-2026-07.md) (the point-in-time security assessment: methodology, findings, verified strengths, accepted risks), [`poam.md`](ato/poam.md) (Plan of Action & Milestones — the open security/technical findings), [`control-implementation.md`](ato/control-implementation.md) (NIST 800-53 control → implementation/documentation matrix), [`fips-199-categorization.md`](ato/fips-199-categorization.md) (information types + C-I-A categorization), [`ato-package-gaps.md`](ato/ato-package-gaps.md) (register of ATO artifacts not yet authored, with stubs), and `diagrams/` (hand-laid-out SVGs generated by [`ato/diagrams/generate.py`](ato/diagrams/generate.py) — edit the script, re-run, commit both; never Mermaid) | Security reviewers / AO |
| [`operations/`](operations/) | Operator docs: [`greenfield-deployment.md`](operations/greenfield-deployment.md) (**start here** — empty VPC → authenticated client, incl. the org-prerequisite request phase and the end-to-end validation checklist), [`om-runbooks.md`](operations/om-runbooks.md) (steady state: rotation, updates, alarms, backup/restore, teardown), [`troubleshooting.md`](operations/troubleshooting.md) (symptom-indexed: what you see → cause → fix), [`cost-controls.md`](operations/cost-controls.md) (spend caps, dashboards, fail-closed incident response), [`client-config.md`](operations/client-config.md) (Part I: developer user manual — prerequisites, install, sign-in, troubleshooting; Part II: managed-settings enforcement model), [`monitoring-and-retention.md`](operations/monitoring-and-retention.md) (alarms, SNS notification contract, every log/metric destination with retention + encryption) | Operators |
| [`requests/`](requests/) | Copy-paste request templates for the org teams whose actions gate a deploy: [`networking-request-email.md`](requests/networking-request-email.md) (cert/DNS/Zscaler), [`okta-request-email.md`](requests/okta-request-email.md) (OIDC app + groups claim), [`ad-request-email.md`](requests/ad-request-email.md) (GPO managed setting) | Operators → org teams |
| [`generated/`](generated/) | PDF renderings of the source docs, mirroring the source folder structure — `generated/ato/*.pdf`, `generated/operations/*.pdf`, `generated/requests/*.pdf` — plus [`user-manual.pdf`](generated/user-manual.pdf) (the developer handout: Part I of `client-config.md`, extracted by `md-to-pdf.py`; its path is fixed — `publish-portal-release.sh` uploads it to the portal). Regenerate with `make docs-pdf` ([`md-to-pdf.py`](md-to-pdf.py), needs `weasyprint`+`markdown` from `scripts/requirements-tools.txt`) in the same change that edits a source doc or diagram. | Reviewers who want files, not markdown; `user-manual.pdf` → end users |

**Every source `.md` under `ato/`, `operations/`, and `requests/` has a PDF
partner** at the mirrored path under `generated/` — `make docs-pdf` discovers
the sources automatically, so a new doc gets its PDF with no script change.
One extra PDF ships alongside the set: `user-manual.pdf` at the `generated/`
root, the end-user handout extracted from `client-config.md` Part I by
`md-to-pdf.py` — the administrator half (Part II) is in the full
`client-config.pdf` partner.
